<task type="auto">
  <name>Task 1: Duplicate registration never mints a token without proof (C1)</name>
  <files>src/worker/routes/public.ts, tests/worker/public.test.ts</files>
  <action>
In `returningResponse` (public.ts ~line 110) only rotate/issue a token when the
request already proves ownership of that user: a valid `s60_token` cookie,
`Authorization: Bearer`, or `?t=` that resolves to the SAME user id. Otherwise return
`apiError(ERROR_CODES.DUPLICATE, "This email or WhatsApp number already has a seat. Open your Launchpad from the link you saved.")` — no token, no set-cookie, no launchpadUrl.
Rate-limit duplicate attempts per identifier: KV key `register-dup:{sha256(email|phone)}`
with 10/h (reuse `rateLimit` + `c.env.CACHE`). Keep the existing insert-race path
(unique constraint → look up → same behavior). Update tests: duplicate without token
→ 409 `DUPLICATE` and the victim's original token still works; duplicate WITH the
victim's token/cookie → 200 `isReturning: true` and a rotated token works.
  </action>
  <verify>npx vitest run tests/worker/public.test.ts</verify>
  <acceptance_criteria>
    - grep public.ts for `ERROR_CODES.DUPLICATE`
    - duplicate-without-proof test asserts 409 and `res.headers.get("set-cookie") === null`
    - duplicate-with-token test asserts 200 and a new token different from the old one
  </acceptance_criteria>
</task>
